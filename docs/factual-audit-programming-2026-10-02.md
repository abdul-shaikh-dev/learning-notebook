# Programming lesson factual audit - 2026-10-02

Baseline: `4efaedb`. Scope: 250 canonical lessons across 11 paths. Every lesson takeaway, section, example, exercise prompt/solution/check and quiz was read; the five embedded traces were read too. The 30 problem-solving lessons were checked against `challenges.json`, including constraints, approaches, complexity, pitfalls and all supplied cases. Generated copies were not treated as additional lessons.

This is a full reading record with bounded verification, not a proof of every possible input, runtime or deployment. The table identifies each lesson and its evidence. A passing reference test is evidence about that implementation and fixture; it does not validate an arbitrary learner solution. Teaching recommendations were assessed against their stated scenario rather than presented as universal facts.

## Executed evidence

- Python 3.14.0: 121 parseable example/solution blocks across 67 lessons ran successfully in temporary copies. The 68th lesson, algorithm-review, has prose instead of executable Python. Blocks within a lesson shared definitions; prose and command transcripts were reviewed rather than treated as runnable Python.
- All 30 canonical challenge solutions matched 192 supplied cases and 60 examples. Deep-copy comparisons found no input mutation in those inputs. These are supplied finite cases, not exhaustive proof. The primary reviewer also ran all 30 references and 192 cases through the real vendored Pyodide browser worker, plus invalid-result cases.
- Fresh temporary-copy unittest suites: Python 26, DSA 10, patterns 25, requirements 13, testing 18, Git 8 ; 100 tests passed. The initial subset excluded the Python installed-package test; the primary agent subsequently ran scripts/verify-python.py on Python 3.14, including packaging build and test_installed_package.py (53 unittest runs, 364 tests). Python 3.11 was not executed in this pass. Git fixtures used owned local repositories and synthetic identity; no hosting/push behavior was tested.
- React: domain assertions plus 11 Vitest tests across 3 files passed with installed dependencies. These are Node/jsdom checks, not a browser/assistive-technology walkthrough.
- Full stack: `node --experimental-strip-types planner-api.test.ts` passed. No full-stack UI dependency install, .NET 10 server execution or SQL Server integration run was made in this audit.
- UI: `node contrast.test.cjs` and `node semantics.test.cjs` passed. #777777/white calculated 4.478089453577214; #595959/white 7.004729208035935. Static checks do not establish WCAG conformance.

## Corrections

- UI contrast: separate WCAG style-color measurement from the perceived effect of anti-aliasing; do not sample smoothed glyph-edge pixels for the criterion.
- UI dragging: explicitly require a non-drag single-pointer alternative as well as keyboard access.
- Testing concurrency/flakiness: join timeout bounds waiting but does not terminate the worker; retain is_alive and bounded worker-operation checks.
- React resilience/security: replace unrelated Web Storage reference with React Error Boundary and OWASP XSS guidance.
- Full-stack delivery: distinguish server runtime configuration from Vite build-time environment substitution.

## Limits applying to the rows

- .NET: installed SDKs were 8.0.425 and 9.0.318; target .NET 10 was unavailable. Microsoft API/support documentation was consulted, but all .NET 10 compile/runtime, authentication, database and deployment results remain unexecuted. No target was silently downgraded.
- Source checks used primary documentation excerpts relevant to the claims. A source link is not a claim that every line of its complete book/site was read. GoF lessons linked only to the publisher catalog remain source-limited: local semantics and Python examples were reviewed, but the complete 1994 book text was not available. Author excerpts support Adapter, Abstract Factory and Chain of Responsibility; Fowler supports DI, Repository, Unit of Work and refactoring.
- MIT lecture 15 PDF was also read for memoization, bottom-up ordering and recurrence analysis; DP rows use that primary text. The primary reviewer read the MIT 6.046J lecture 1 PDF, pages 2-4, for earliest-finish greedy scheduling. Knapsack retains the index-only source limit. Local invariants and finite oracle tests are not a full independent proof for all valid inputs.
- Browser keyboard/zoom/screen-reader combinations, actual user research, production releases, SQL backup/restore and remote services were not executed. Their lesson descriptions were reviewed as instructions or scenarios.
