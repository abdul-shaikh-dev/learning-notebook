# Optional permanent schema, migration and permission lab

Use a disposable training database named `LearningNotebookLab_<suffix>` where you may create schema, tables, a role and a contained test user. The scripts check this name prefix before changing anything. This lab changes permanent objects in **the current database**. Confirm `SELECT DB_NAME()` before running. Do not use a shared or production database. Run `schema-permissions-lab.sql` twice, in one query window or separate windows; unlike the main temporary-table exercises, these objects persist.

Expected observations: the customer/order join returns Ada and order 101 once after each run; the orphan insert raises a foreign-key error and no order 999 remains; `MissingSourceCode` is zero after the nullable expand and backfill. Review the commented contract step before making the column required. A real migration needs an inventory of old writers, batch/backfill limits, deployment ordering, backup/recovery and a rollback plan. Re-running this illustrative script is only a local replay check.

The script creates `ln_lab_probe` without a login, grants SELECT through `ln_lab_reader`, and uses `EXECUTE AS USER` to check one visible row and an INSERT denial (error 229). Its catch block reverts the impersonation before checking the error. Record both outputs and confirm order 998 is absent. No login or password is created. Do not grant write permission to make the negative test pass.

Clean up with `schema-permissions-cleanup.sql` only after checking its names and confirming you own this disposable database. The cleanup removes the test membership and user before dropping the role. If other objects refer to this schema, inspect them and coordinate cleanup. Record engine version, database, two-run outputs, FK error, permission denial, migration order and actual cleanup. On 30 September 2026, this optional script ran twice on local SQL Server 2025 Express 17.0.1000.7 in a uniquely named disposable database. Both runs returned one Ada/order 101 row, FK error 547, zero missing SourceCode values, one visible order under the limited user and INSERT denial 229. Guarded cleanup succeeded and the disposable database was dropped. This verifies only this local engine run; repeat and record results in your own environment.
