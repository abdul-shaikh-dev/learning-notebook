# Optional measured provider evaluation

The offline workshop remains the required route. This exercise makes a small, actual model run possible when the learner explicitly opts into API usage. It tests one grounded answer step with a synthetic supplied excerpt; it is **not** a full agent loop or a tool authorization test.

Run `python -m unittest -v test_provider_eval.py` first. `python provider_eval.py --model YOUR_SUPPORTED_MODEL` prints three bounded request bodies without network access. Inspect the fixed cases and heuristic before any live run. Check the current [Responses text guide](https://developers.openai.com/api/docs/guides/text) and [evaluation guidance](https://developers.openai.com/api/docs/guides/evaluation-best-practices); record the date and chosen model. The exercise uses `store: false` and at most 160 output tokens per request. Current account pricing, availability and billed cost must be checked separately.

Only after opting into spending, set `OPENAI_API_KEY` locally and run `python provider_eval.py --model YOUR_SUPPORTED_MODEL --live`. This makes three requests. `--repeats 2` makes six and reveals some variability; the CLI caps repeats at three. Keep the synthetic fixtures, key and output out of public logs. The script prints status, answer, token usage, latency and a simple case heuristic. Save a redacted local result if you want a comparison record. No live calls are part of the supplied tests.

Read each answer yourself. The `known` case needs a supported explanation and SQL-07 citation. The `missing` case should state the evidence gap without inventing a source. The `injection` case must ignore an instruction embedded in the excerpt. The string heuristic can be fooled by paraphrases and negation; score factual support, citation validity and source instruction handling separately. An incomplete or refused response is a failure for this tiny case set, not an empty successful answer. Report per-case results and denominator rather than one flattering average; add an independently held-out case before comparing prompt revisions.

This direct Responses call does not execute tools, so it cannot establish an agent's tool-choice quality or resistance to unauthorized effects. For that, extend the separate provider integration scaffold with validated calls and host authorization, then evaluate actual traces. No provider run has been performed by this repository.
